# AutoMail — 期限と受け取りボード

Gmail に届くメールから「期限」「受け取り」「移動・宿泊」「支払い」に関わる情報を毎日自動で拾い出し、1枚の Web ページ（ボード）と Google カレンダーにまとめ続ける、Claude による自動運転システムです。

もともと Google Drive のフォルダ「期限と受け取りボード」で運用していた仕様書・手順書を、このリポジトリに移したものです。

> **注意：このリポジトリは public です。** メールアドレス・注文番号・予約番号・人名・Drive のファイル ID などの個人情報は書かないでください。実際の値は `config/config.example.md` を参考に、リポジトリの外（Scheduled task の prompt や Drive 上の台帳）で管理します。

## 全体像（どこに何があるか）

| 場所 | 役割 |
|---|---|
| **Scheduled task（Routine）**「期限と受け取りボード」 | 毎日の起動条件と、その日の処理手順の本体。prompt の雛形は [`prompts/scheduled-task.md`](prompts/scheduled-task.md) |
| **このリポジトリ** | 仕様・運用ルールの正本。[`docs/update-procedure.md`](docs/update-procedure.md) に詳細ルールを蓄積 |
| Google Drive `01_記録台帳 YYYY-MM` | 現在の状態のスナップショット（最後に読んだメールの受信時刻・カレンダー登録済みイベントID・未確認事項）。**月に1ファイル** |
| Google Drive `02_メールDB（1件1ブリーフィング）` | 読んだメール全件の生記録。**日に1ファイル**、1メール＝1ブロック。広告・求人も含めすべて残す |
| Artifact「期限と受け取りボード」 | 人間が実際に見る成果物。カレンダー・今日やること・受け取り待ち・期限一覧・お金の動きをまとめた1枚の Web ページ |
| Google カレンダー（primary） | 移動・宿泊・買い物・重要締め切りをイベントとして登録する場所 |

## データフロー（毎回の処理の流れ）

```
Scheduled task 起動（毎日 6/10/12/15/18/20/22/0時 JST、全て00分）
   │
   ▼
① 01_記録台帳 を読む → 「最後に読んだメールの受信時刻」を確認
   │
   ▼
② Gmail search_threads で、その時刻より新しいメールを検索
   （after: は日付単位なので、同日分は時刻で自分でフィルタする）
   │
   ├─ 0件 → 台帳の確認時刻だけ進めて終了
   │
   └─ 1件以上（上限200件・古い順）
        │
        ▼
③ 取引・期限・金額に関わるメールだけ get_thread で本文精読
   広告・キャンペーンは件名だけで分類（軽量運転）
        │
        ▼
④ 02_メールDB のその日のファイルに1メール1ブロックで追記
        │
        ▼
⑤ Artifact を action:"read" → 今回処理した分だけボードに反映 → publish
        │
        ▼
⑥ 移動・宿泊・買い物・重要締め切りを Google カレンダーに登録
   （書き漏れ再発防止の6ステップを実行。詳細は docs/update-procedure.md）
        │
        ▼
⑦ 01_記録台帳 を更新（同月のファイルを trash → 同名で作り直し）
        │
        ▼
⑧ 新しい期限・予定が増えていれば .ics を作って送付
```

200件を超える未処理があるときは、古い順に200件だけ処理して打ち切り、台帳に「残り◯件、続きは次回」と記録します。次回以降の実行で自動的に続きから処理されます。

## ボードの見かた（色分けサマリー）

| 色 | クラス | 意味 | カレンダー登録 |
|---|---|---|---|
| 青紫 | `ce-trip` | 移動（実際に乗る日） | ○ |
| 赤紫 | `ce-stay` | 宿泊（実際に泊まる日） | ○ |
| 青 | `ce-buy` | 買い物（注文・予約・支払い・発送・返金） | ○ |
| シアン | `ce-arrive` | 到着（商品が届く日・配達完了・受け取り待ち） | ×（買い物側で登録済み） |
| 濃い赤 | `ce-due` | 重要締め切り／自分宛メモ由来の重要イベント | ○ |
| 薄い赤 | `ce-minor` | 非重要な締め切り（無料キャンセル期限・自動送金など） | × |
| 橙 | `ce-soon` | 任意の予定・イベント（非重要） | × |
| 灰 | `ce-past` | そのほかの済んだこと | — |
| 破線＋バッジ | `is-ad` | 広告・キャンペーン | × |

ログイン・アカウント関連の心当たりのない通知は、カレンダーではなくボードの「ログイン通知」タブに載せます。

## 運用ルール（要点だけ）

- サブエージェントは使わない。全部自分で直接ツールを呼ぶ（トークン節約）。
- 1回の実行につき最大200件（ユーザーの指示で変更可）。
- 取引・期限・金額に関わるメールだけ本文を精読し、広告は件名だけで分類する。
- 深いページングによる全件再列挙は「調査依頼」があったときだけの特別作業。
- 買い物・移動・宿泊・重要締め切りは、過去日付・完了済み・金額未確定でも省略せず必ずカレンダー登録する。
- 自分宛メモ（本人が自分に転送したメモ）は最優先の重要事項として扱う。
- 日付・金額・商品名は必ずメール本文から取り、推測しない。分からなければ「未確認」と明記する。

詳細と背景（いつ・なぜそのルールができたか）はすべて [`docs/update-procedure.md`](docs/update-procedure.md) にあります。

## まだ直していない論点

1. **カレンダーの重複防止が目視ベース。** 参照番号・注文番号を description に入れて照合する運用で補っている。
2. **迷惑メールの定期チェックがない。** ユーザーの申告時のみ `in:spam` を確認する反応的な運用。
3. **台帳・メールDBの履歴が残りにくい。** trash → 作り直し方式のため、過去の状態は Drive のゴミ箱から追う必要がある。
4. **Outlook 側の転送設定はこのシステムからは直せない。** ユーザー側の作業が必要。
